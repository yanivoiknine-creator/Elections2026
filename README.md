# מעקב סקרים – בחירות 2026

אפליקציה מקומית שאוספת את סקרי המנדטים מאתרי הערוצים, מציגה עמוד לכל מקור,
גרף מגמה לכל מפלגה, ובעמוד הראשי את ממוצע הסקר האחרון מכל מקור.

## התקנה והפעלה

```
setup.bat      # פעם אחת: מתקין תלויות וטוען היסטוריית סקרים
run.bat        # הפעלה — נפתח אוטומטית ב-http://127.0.0.1:8000
```

או ידנית:

```
python -m pip install -r requirements.txt
python seed.py      # אופציונלי — טוען ~200 סקרים היסטוריים
python app.py
```

**אם האפליקציה לא מגיבה לשינויים** — כנראה מופע קודם עדיין תפוס על פורט 8000.
`app.py` מזהה את זה ועוצר עם הודעה ברורה במקום להיכשל בשקט; סגרו את החלון
שבו הוא רץ, או:

```
powershell -Command "Get-NetTCPConnection -LocalPort 8000 -State Listen | ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }"
```

## פרסום ברשת (GitHub Pages) — צפייה מכל מכשיר

האפליקציה יודעת לבנות את עצמה כ**אתר סטטי** ולהתפרסם בחינם ב-GitHub Pages,
כך שאפשר להיכנס אליה מהטלפון או מכל מחשב בלי שהמחשב שלכם ידלוק.

### הקמה חד-פעמית — העלאה ידנית דרך האתר של GitHub

התיקייה `_upload/` נוצרת על ידי `python make_upload.py` ומכילה בדיוק את מה
שצריך לעלות, בלי קבצים מיותרים.

1. ב-GitHub: **New repository**, תנו שם, ו-**Create repository**.
2. במאגר הריק: **Add file → Upload files**, וגררו לשם את **כל התוכן** של
   `_upload/` **חוץ מהתיקייה `_קבצים-מיוחדים`**. לחצו **Commit changes**.
3. שני קבצים ששמם מתחיל בנקודה לא עוברים בגרירה, ולכן יוצרים אותם ידנית —
   **Add file → Create new file**, ובשורת שם הקובץ מקלידים את הנתיב המלא
   (הקלדת `/` יוצרת תיקיות):
   * `.github/workflows/update.yml` — התוכן מתוך `_קבצים-מיוחדים/update.yml`
   * `.gitignore` — התוכן מתוך `_קבצים-מיוחדים/gitignore.txt`
4. **Settings → Pages → Source** בחרו **GitHub Actions**.
5. **Settings → Actions → General → Workflow permissions** בחרו
   **Read and write permissions** (כדי שהמשימה תוכל לשמור סקרים חדשים).
6. **Actions → עדכון סקרים ופרסום האתר → Run workflow** להרצה ראשונה.

**עדכון קבצים בהמשך:** בהעלאה ידנית פשוט מעלים שוב את הקובץ ששונה — GitHub
מזהה שזה אותו נתיב ומחליף אותו. `data/polls.json` מתעדכן לבד על ידי המשימה
המתוזמנת, אז אין צורך להעלות אותו שוב.

האתר יעלה בכתובת `https://<המשתמש>.github.io/<המאגר>/`.

### מה קורה מכאן

משימה מתוזמנת רצה **כל 3 שעות**: גורדת את כל שמונת האתרים, שומרת סקרים
חדשים ובונה את האתר מחדש. אפשר גם להריץ ידנית בלחיצה מלשונית Actions.

* **הנתונים נשמרים ב-`data/polls.json`** ולא בקובץ SQLite. JSON הוא טקסט,
  הדיפים שלו קריאים והוא נדחס היטב; קובץ בינארי היה מנפח את היסטוריית
  ה-Git בכל הרצה. מסד הנתונים נבנה מה-JSON בתחילת כל ריצה.
* **הצינור אידמפוטנטי** — הרצה בלי סקרים חדשים לא משנה את ה-JSON ולכן לא
  יוצרת commit. נבדק על שלוש הרצות רצופות.
* **אם אתר נחסם או נופל** — הצינור ממשיך, האתר נבנה מהנתונים השמורים, והמצב
  של כל מקור מוצג בעמוד הראשי. עדיף אתר עם נתוני אתמול מאשר בנייה שנכשלת.

### מגבלות שכדאי להכיר

* אין כפתור "בדוק עכשיו" באתר הפומבי — אין שם שרת שיגרד. במקומו מוצג מתי
  בוצעה הבדיקה האחרונה, והעדכון קורה לפי לוח הזמנים.
* אתרי החדשות עשויים לחסום כתובות של שרתי ענן חזק יותר מאשר חיבור ביתי.
  אם מקור נחסם ב-GitHub, זה יופיע כשגיאה בכרטיס שלו בעמוד הראשי.
* GitHub משבית משימות מתוזמנות במאגר שאין בו פעילות 60 יום. די בהרצה ידנית
  אחת כדי להחיות אותן.

הפעלה מקומית של אותו צינור, לבדיקה לפני דחיפה:

```
python pipeline.py        # נתונים -> גרידה -> בניית האתר ל-docs/
python build_static.py    # בנייה בלבד, בלי גרידה
```

## צפייה מהטלפון (בלי אינטרנט, ברשת הביתית)

```
run-lan.bat          (או:  python app.py --lan)
```

האפליקציה תדפיס בקונסולה את הכתובת שאליה נכנסים מהטלפון, יחד עם **קוד QR**
לסריקה עם המצלמה:

```
==============================================================
  מהטלפון, באותה רשת Wi-Fi:   http://192.168.0.217:8000
==============================================================
```

* הטלפון והמחשב חייבים להיות על **אותה רשת Wi-Fi**.
* המחשב צריך להישאר דלוק והאפליקציה פתוחה.
* **אם הטלפון לא מתחבר** — חומת האש של Windows חוסמת. פתחו PowerShell
  כמנהל והריצו פעם אחת:
  ```
  New-NetFirewallRule -DisplayName "Elections2026" -Direction Inbound -Protocol TCP -LocalPort 8000 -Action Allow
  ```
* כתובת ה-IP מזוהה אוטומטית לפי הכרטיס שדרכו המחשב יוצא לאינטרנט, כך שאין
  בלבול בין Wi-Fi, כבל, ומתאמים וירטואליים של WSL או Docker.

`run.bat` הרגיל מאזין ל-`127.0.0.1` בלבד — כלומר רק מהמחשב עצמו. `--lan`
פותח את האפליקציה לכל מי שנמצא על הרשת, ואין בה שום מנגנון הרשאות; זה בסדר
ברשת ביתית, אבל לא כדאי ברשת ציבורית.

הממשק מותאם למסך טלפון: הכל נערם לעמודה אחת, ובטבלאות הרחבות שם המפלגה
נשאר מוצמד בצד בזמן גלילה אופקית.

### בדיקת סקרים חדשים

בכותרת, מתחת לכפתור, מוצג תמיד **"נבדק לאחרונה: תאריך, שעה"** — כך שבכל עמוד
אפשר לדעת עד כמה הנתונים טריים. הזמן נשמר ב-UTC ומוצג בשעון המקומי, מתעדכן
מיד בסיום בדיקה בלי לטעון את העמוד מחדש, וצובע את עצמו בכתום אם עברו יותר
מ-12 שעות. ריחוף מציג "לפני X דקות".

* **אוטומטית עם כל פתיחה של האפליקציה** — ברגע שהשרת עולה הוא מתחיל לבדוק את
  כל האתרים. הבדיקה רצה **ברקע**, כך שהעמוד נפתח מיד (0.2 שניות) ולא ממתין
  לה. בזמן הבדיקה מוצג באנר בראש העמוד, ואם נמצא סקר חדש העמוד מתרענן לבד.
  אם אין חדש — מוצגת הודעה קצרה והבאנר נעלם. סבב מלא על 8 האתרים אורך
  כ-8 שניות.
  לכיבוי: `python app.py --no-refresh` או `ELECTIONS_NO_AUTO_REFRESH=1`.
* **כפתור "בדוק סקרים חדשים"** (בכל עמוד) מפעיל בדיקה ידנית. בעמוד של מקור
  מסוים הוא בודק רק אותו. לחיצה בזמן שבדיקה כבר רצה לא מפעילה בדיקה כפולה —
  הממשק פשוט נצמד לזו שרצה.

### הערות על איכות הנתונים

* **חסימות בוט** — `kan.org.il` מוגן ב-Cloudflare ו-`13tv.co.il` ב-Akamai, ושניהם
  חוסמים לקוחות HTTP רגילים לפי טביעת אצבע TLS. לכן האפליקציה משתמשת ב-`curl_cffi`
  שמחקה ClientHello של כרום אמיתי.
* **הרשימות הערביות ב-API של ערוץ 14** — ערוץ 14 אינו מפרסם שם את הרשימות הערביות
  המאוחדות, ולכן ב-API הן מגיעות כאפס והסקר מסתכם בפחות מ-120. בכל סקר כזה
  בדקנו שכל הרשימות הערביות מאופסות יחד ושהפער בדיוק בגודל הבלוק הערבי
  (רע"ם מדווח -> פער 4-7 = הרשימה המשותפת; גם רע"ם מאופס -> פער 11-13 = כל
  הבלוק). לכן ההפרש ל-120 מיוחס לרשימה המשותפת, ומסומן בממשק כ-"מושלם".
  ההשלמה **שמרנית**: היא פועלת רק כשאף רשימה ערבית לא דווחה. פערים אחרים —
  למשל 4 מנדטים של "הבית הציוני" ביולי, שערוץ 14 גם לא דיווח — נשארים
  כפי שהם, כי שם ההשלמה הייתה מייחסת מנדטים למפלגה הלא נכונה.
  כתבות הסקר באתר ערוץ 14 עצמו כן מפרטות את הרשימות הערביות, ומאשרות שההשלמה
  מדויקת: הכתבה מ-24.8 מציינת חד"ש-תע"ל-בל"ד 5 — בדיוק הפער שחושב.
* **בעלות על הסקר** — מעריב, i24 וישראל היום מסקרים באותו עמוד תגית גם סקרים
  של ערוצים אחרים. למשל "סקר מנדטים: הליכוד מגיע לשפל חדש" במעריב הוא בעצם
  סקר של חדשות 13. בלי בדיקה, סקר של גוף אחד היה נרשם על שם גוף אחר, ולכן כל
  מקור מגדיר ביטוי שחייב להופיע בכתבה (מכון לזר, דיירקט פולס, יוסי טאטיקה...).
* **בדיקת סבירות** — לפני שמירה נבדק שסך המנדטים בטווח 100–130, שאין מפלגה מעל
  45 מנדטים, ושזוהו לפחות 8 מפלגות. כתבה שנראית כמו סקר אבל היא בעצם תרחיש
  היפותטי ("כמה שווה מפלגת X") נפסלת, והאפליקציה עוברת לכתבה הבאה.
* **כפילויות** — הארכיונים מתארכים סקר לפי יום הפרסום, והגרף שבכתבה לפי יום
  הדגימה. אותו סקר בהפרש של יום-יומיים עם אותן תוצאות מאוחד לרשומה אחת,
  ומעדיפים את הגרסה שנגרדה מהאתר עצמו.

## הממוצע בעמוד הראשי

ממוצע של **הסקר האחרון מכל מקור**, מנורמל ל-120 מנדטים.

* מפלגה נספרת רק במקורות שבסקר האחרון שלהם היא מופיעה. `–` בטבלה = לא מופיעה
  כלל; `0` = המקור דיווח עליה במפורש כלא עוברת את אחוז החסימה (וזה כן נספר).
* **למה צריך נרמול** — כל סקר בנפרד מסתכם ב-120, אבל סכום הממוצעים לפי מפלגה
  לא בהכרח. מפלגה שרק חלק מהסוקרים מדדו אותה מחולקת במספר קטן יותר משאר
  המפלגות, וזה מנפח את הסכום. למשל מפלגת וינטר, שהושקה ב-25.8: סקרים שפורסמו
  לפניה כלל לא שאלו עליה, ולכן היא מחולקת ב-6 בעוד השאר ב-8 — תוספת של
  0.75 מנדטים (18/6 = 3.00 לעומת 18/8 = 2.25).
  לחלק אותה במספר המלא היה מניח בטעות שמי שלא שאל נתן לה אפס, ולכן במקום זה
  כל המפלגות נמתחות באותה פרופורציה. היחסים נשמרים, והמפה מסתכמת ב-120.
  הערך הגולמי זמין בריחוף מעל המספר בטבלה וב-`raw_avg` ב-API.
* בממוצע בלבד, `חד"ש-תע"ל` ו-`בל"ד` מאוחדים ל-`הרשימה המשותפת`. בלי זה אותם
  מנדטים היו נספרים פעמיים, כי חלק מהמקורות מדווחים רשימה מאוחדת וחלק מפוצלת.
  בעמוד של כל מקור מוצג הפירוט המקורי כפי שפורסם.
* גרף המגמה של הממוצע: לכל תאריך שבו פורסם סקר כלשהו נלקח מכל מקור הסקר האחרון
  שלו נכון לאותו יום (עד 45 יום אחורה), והתוצאות מוצעות.

## הוספת אתר חדש

1. צור `scrapers/<שם>.py` עם פונקציה `latest()` שמחזירה:
   ```python
   {"poll_date": "2026-08-24", "results": {"likud": 22, ...},
    "title": ..., "url": ..., "pollster": ..., "raw": {...}}
   ```
   המפתחות ב-`results` הם מזהים קנוניים מ-`parties.py`. אפשר להשתמש ב-
   `parties.match_party("שם המפלגה כפי שמופיע באתר")` כדי לקבל אותם.
2. הוסף רשומה ל-`SOURCES` ב-`sources.py` ואת המפתח ל-`ORDER`.

זה הכל — העמוד, הגרף, הכפתור והממוצע נוצרים אוטומטית.

`scrapers/common.py` נותן את רוב העבודה בחינם: `collect_links` לאיתור כתבות
בעמוד תגית, `is_own_poll` לבדיקת בעלות, `seats_from_infograms` לגרפי Infogram,
ו-`chart_date` לתאריך מכותרת הגרף.

אם הסקר מופיע כטקסט חופשי, `scrapers/text_parser.py` מחלץ מנדטים מפרוזה עברית.
הוא עובד משפט-משפט, מדלג על משפטי תרחיש היפותטי, ומבחין בין תוצאה
("מקבלת 9 מנדטים"), שינוי ("עלייה של שלושה מנדטים") וסכום גוש ("גוש נתניהו על 51").
אחרי שינוי בפרסר — הריצו `python test_parser.py`, שבודק אותו מול כתבות אמיתיות
מכל האתרים.

## מבנה

```
app.py              שרת FastAPI + נתיבים (הרצה מקומית)
```
